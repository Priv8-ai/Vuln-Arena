One host. The calls you already make.

Relaywork is not a mesh and not a portal. It is the console in front of login, notes, profile, GraphQL, merge, and health.

  1. Exchange a password for a session. POST /auth/login with user and pass. The response carries the bearer token later calls send.
  2. Read a note by id. GET /api/notes/:id returns the owner and the body recorded for that id.
  3. Update the profile document. POST /api/profile writes the fields you send onto the signed-in profile.
  4. Ask GraphQL. POST /graphql accepts a query document. Users and the schema are both queryable from that route.
  5. Merge a config object. POST /api/merge folds a JSON document into the working copy your service just built.
  6. Check health. GET /health answers { ok: true } for the load balancer. The same route can answer more when an operator asks.

Token on the wire

Send Authorization: Bearer with the token from login. The console does not keep a second session store.

JSON in, JSON out

Profile, merge, and GraphQL all speak JSON. The batch helper reads the raw document from the X-Raw-Json header when you need it.

Stay on the private network

Relaywork is meant to sit next to the services that call it. There is no public signup desk.
