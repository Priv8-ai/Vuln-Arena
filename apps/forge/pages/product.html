A hook, a job, a name, a file.

Foundry CI does not invent a new build system. It runs the four calls a plant already makes when a webhook should become a job.

Test the hookPOST /hooks/test with a url. The forge fetches it and returns the front of the body.
Queue the jobPOST /jobs with a cmd and an owner. You get an id while the run is pending.
Read it backGET /jobs/{id} returns the record for that id.
Name and collectGET /template?name= renders the greeting. GET /download?f= returns the stored file.
